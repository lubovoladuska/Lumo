# Design

## Context

См. proposal.md. Навыки и режимы ответа уже есть (`skill-system`, `reply-styles`); быстрый путь должен лишь подставить вызов навыка вместо решения LLM.

## Decisions

### 1. Шаблоны на регулярных выражениях по всей фразе
`fast_commands.match(text) -> FastCommand(skill, params) | None`. Фраза нормализуется (регистр, ё→е, пунктуация, имя «Вальтер» в начале, «пожалуйста», числа словами → цифры) и должна совпасть с шаблоном **целиком** (`fullmatch`). Любое лишнее слово → LLM. Ложное срабатывание хуже лишнего запроса.
- Альтернатива: маленькая локальная модель-классификатор — отклонено: сложнее, медленнее на CPU, а набор команд мал и стабилен.

### 2. Выполнение через тот же реестр навыков
Быстрый путь вызывает `registry.prepare` + `registry.run` с тем же `SkillContext`, пишет `tool_log` и историю (реплика + ответ с tool_calls) — для LLM в следующих репликах это неотличимо от обычного вызова. Ответ — `direct_reply`; для навыков с полным ответом текст берётся из форматтера команды (время) или результата навыка; ошибка озвучивается её текстом без префикса «Ошибка:». Навыки с `confirm=True` в быстрый путь не попадают. Отключённый навык → LLM.

### 3. Кэш DeepSeek: постоянное в начало
DeepSeek кэширует совпадающий префикс запроса. Системное сообщение = персона + правила + факты (меняется только при «запомни/забудь»). Время, день недели и часовой пояс — отдельным системным сообщением сразу перед текущей репликой. Список инструментов стабилен (порядок обнаружения).

### 4. Учёт токенов
`OpenAICompatibleClient` логирует `prompt_tokens`, `completion_tokens` и `prompt_cache_hit_tokens` (поле DeepSeek). Быстрые команды логируются строкой «Быстрая команда … (без LLM)».

## Risks / Trade-offs

- [Шаблон сработал не по смыслу] → только полное совпадение фразы; тесты на «похожие, но не те» фразы.
- [Whisper пишет числа по-разному («30», «тридцать», «30%»)] → нормализация чисел словами до 100 и знака процента.
