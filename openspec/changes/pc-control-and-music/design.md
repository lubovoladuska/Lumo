# Design

## Context

Ядро (FastAPI + WebSocket) работает только с текстом, навыки живут в `core/skills/` и выполняются в процессе ядра. ПК-клиент держит одно WebSocket-соединение и аудиодвижок `EchoCancellingAudio` (48 кГц моно, WebRTC AEC, один канал воспроизведения для речи). Пользователь на Windows 10, ПК и ядро на одной машине, часовой пояс берётся из системы. Мотивация — proposal.md, требования — specs/.

Важная особенность текущего сервера: реплика обрабатывается прямо в цикле чтения сообщений клиента (`await assistant.handle_utterance(...)`).

## Goals / Non-Goals

**Goals:**
- Общий механизм «навык ядра → действие на устройстве → результат», не завязанный на ПК.
- Всё, что трогает Windows и звук, выполняется в ПК-клиенте; ядро остаётся без зависимостей от Windows.
- Музыка играет через тот же аудиодвижок, что и голос, чтобы AEC вычитал её из микрофона.

**Non-Goals:**
- Выбор устройства голосом («включи музыку на телефоне») — пока устройство выбирается автоматически.
- Потоковое декодирование, кроссфейд, эквалайзер.
- Управление окнами по одному (переключение, перемещение) — только «свернуть всё» и активное окно.

## Decisions

### 1. Протокол: возможности в `hello`, сообщения `action_request` / `action_result`
`Hello.capabilities: list[str] = []` — старые клиенты совместимы. `ActionRequest(id, action, params: dict)` от ядра к клиенту, `ActionResult(id, ok, text)` от клиента к ядру. Имена действий — `<возможность>.<глагол>`: `pc.app_open`, `music.play`. Возможность действия — префикс до точки.
- Альтернатива: отдельный HTTP API на клиенте — отклонено, клиент за NAT (телефон), а WebSocket уже есть.

### 2. Сервер обрабатывает реплики отдельными задачами
Цикл чтения клиента больше не ждёт `handle_utterance`: для каждой реплики создаётся задача, ответ отправляется, когда готов. Иначе навык, ждущий `action_result` от того же клиента, заблокирует чтение этого результата (взаимная блокировка). Реплики одного клиента выполняются последовательно (очередь на соединение), чтобы не перепутать порядок диалога и подтверждений.

### 3. `DeviceRouter` в ядре
Хранит `Connection.capabilities`, отправляет запрос, ждёт `Future` по `id` (таймаут 15 с), при отключении клиента отменяет его ожидания. Выбор клиента: устройство текущей реплики, если у него есть возможность, иначе подключившееся последним. Навыки получают его через `SkillContext.devices` и вызывают `await ctx.devices.run("pc.volume_set", {...}, origin=ctx.device_id)`. Ошибки превращаются в текст для LLM («Компьютер сейчас не подключён», «Устройство не ответило»), как и другие ошибки навыков.

### 4. Навыки ядра — тонкие, логика на клиенте
Навыки в `core/skills/pc.py` и `core/skills/music.py` описывают параметры для LLM, отмечают подтверждение (`pc_power` с `confirm=True` для выключения, перезагрузки и сна) и пересылают действие. Вся работа с Windows и Яндекс Музыкой — в `desktop/actions/`. Ядро не знает про Windows и может переехать на сервер без изменений.
- Подтверждение остаётся в ядре: это уже проверенный механизм, LLM не может подтвердить сама.

### 5. Исполнитель действий в ПК-клиенте
`ActionExecutor` — реестр `имя → async handler(params) -> str`. Блокирующие вызовы Windows — через `asyncio.to_thread`. Исключения → `ActionResult(ok=False)`. `CoreConnection` получает обработчик `action_request` и отвечает результатом; возможности клиента = возможности зарегистрированных обработчиков (`music` — только если задан токен Яндекс Музыки).

### 6. Приложения: `Get-StartApps` + нечёткий поиск
При старте клиент один раз выполняет PowerShell `Get-StartApps` (имя + AppID), это покрывает обычные и Store-приложения. Запуск — `explorer.exe shell:AppsFolder\<AppID>`. Поиск: нормализация, транслитерация кириллицы и `difflib`-сходство; LLM просим передавать название как в Windows (обычно по-английски), транслитерация страхует. Синонимы: «браузер» → браузер по умолчанию из реестра.
- Закрытие: процессы по имени exe через `psutil`, их окнам отправляется `WM_CLOSE` (как крестик), без принудительного завершения.
- Альтернатива: обход `.lnk` в папках меню «Пуск» — не видит Store-приложения.

### 7. Звук, медиа, питание, окна
- Громкость читается через `pycaw`, а меняется нажатиями клавиш громкости: «усилители» вроде FxSound пересылают громкость на настоящие колонки только по клавишам. Медиа-клавиши и «свернуть всё» — `keybd_event` через `ctypes`.
- Питание — `shutdown /s|/r /t N`, отмена `shutdown /a`, сон — `SetSuspendState`, блокировка — `LockWorkStation`.
- Скриншот — `mss` (все мониторы) в `~/Pictures/Lumo/screenshot-ГГГГ-ММ-ДД-ЧЧММСС.png`. Активное окно — `GetForegroundWindow` + `GetWindowTextW`.
- «Пауза»/«дальше» — одно действие `pc.media`: если играет встроенный плеер, управляет им, иначе нажимает медиа-клавишу.

### 8. Яндекс Музыка: библиотека `yandex-music` (async-клиент)
Поиск `search(type='all')` → лучший результат (трек/исполнитель/альбом/плейлист); исполнитель → популярные треки; «Моя волна» — станция `user:onyourwave` с подгрузкой следующей пачки при подходе к концу очереди и отправкой фидбэка о начале трека; любимые — `users_likes_tracks()`; лайк — `users_likes_tracks_add`. Прямые ссылки на mp3 через `get_download_info(get_direct_links=True)`, выбираем 192 кбит/с.
- Токен — `LUMO_YANDEX_MUSIC_TOKEN` в `.env`; пользователь получает его сам по инструкции в README. Клиент токен никуда, кроме API Яндекса, не отправляет и маскирует в логах.
- Альтернатива: открывать music.yandex.ru в браузере — отклонено: нельзя надёжно включить конкретный трек, нет приглушения и AEC.

### 9. Плеер: загрузка → `miniaudio` → второй канал аудиодвижка
Трек скачивается целиком (несколько МБ), декодируется `miniaudio` в 48 кГц стерео float32 в отдельном потоке, следующий трек готовится заранее, пока играет текущий. Аудиодвижок переходит на **стерео-вывод**: голос дублируется в оба канала, музыка играет в стерео; в AEC идёт моно-сумма того, что реально ушло в колонки.
- Микширование в колбэке вывода: `out = voice + music * music_gain * duck_gain`, ограничение до [-1, 1].
- Приглушение: `duck_gain` плавно (~150 мс) уходит к 0.15, пока ассистент говорит или пишет команду, и возвращается к 1.0 после.
- Альтернатива: VLC/mpv как внешний плеер — отклонено: их звук не попадает в AEC, перебивать поверх музыки нельзя.

### 10. Потоковое воспроизведение и медиапанель Windows
На медленном канале трек качается больше минуты, поэтому плеер играет его по мере загрузки: aiohttp отдаёт куски в `ByteStream`, miniaudio декодирует поток в отдельном потоке в растущий буфер `TrackAudio`, трек стартует, когда накоплено ~2 с звука. Следующий трек начинает грузиться только после полной загрузки текущего.
Встроенный плеер регистрируется в System Media Transport Controls (пакеты `winrt`): трек виден над ползунком громкости, кнопки и медиа-клавиши управляют плеером.
- Альтернатива: играть в приложении Яндекс Музыки — отклонено: его звук не попадает в AEC (нельзя звать и перебивать поверх музыки), а включить конкретный трек по ссылке нельзя.

### 11. Ограничение вызовов навыков
Цепочки вида «найди и включи» укладываются в 1–2 вызова; лимит 5 вызовов на реплику не меняется.

## Risks / Trade-offs

- [Неофициальный API Яндекс Музыки может сломаться или ограничить доступ] → вся работа с ним изолирована в `desktop/actions/music.py`; ошибка API превращается в понятный ответ; для полных треков нужна подписка Плюс — без неё API отдаёт 30-секундные превью, об этом скажем в README.
- [Неточный поиск приложения запустит не то] → порог сходства; при сомнении (два близких варианта) ассистент переспрашивает, а не запускает.
- [Стерео-вывод и микширование в колбэке нагружают аудиопоток] → операции numpy на блоках по 10 мс, декодирование заранее в отдельном потоке; проверка отсутствия щелчков вручную.
- [AEC хуже вычитает громкую музыку на дешёвых колонках] → приглушение под команду + проверка вручную; при проблемах — `LUMO_BARGE_IN=name`.
- [Действия от лица пользователя опасны (выключение)] → подтверждение в ядре, сон/выключение/перезагрузка только после «да».
- [`Get-StartApps` медленный (~1–2 с)] → один раз при старте клиента и по требованию «обнови список приложений».

## Migration Plan

Протокол обратно совместим: клиенты без `capabilities` работают как раньше. Аудиодвижок меняет формат вывода на стерео — затрагивает только ПК-клиент. Новые зависимости ставятся `uv sync --extra desktop`. Откат — предыдущая версия клиента и ядра.
