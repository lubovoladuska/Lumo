# Design

## Context

Проект с нуля, кода нет. Ограничения: Windows 10, GTX 1660 Ti (6 ГБ, без быстрого float16), бюджет только на DeepSeek API, в будущем — Android-клиент и умный дом. Мотивация — см. proposal.md, требования — см. specs/.

## Goals / Non-Goals

**Goals:**
- Чёткое разделение: **ядро думает и помнит, клиенты слушают и говорят**. Ядро работает только с текстом.
- Каждый тяжёлый компонент (STT, TTS, слово-активатор, LLM) спрятан за интерфейсом, чтобы его можно было заменить без переделки остального.
- Всё, кроме LLM, работает офлайн.

**Non-Goals:**
- Несколько пользователей и регистрация: в MVP один владелец (`user_id = "owner"`), но поле есть в схеме данных.
- Синхронизация через интернет: в MVP связь только локальная; удалённый доступ для телефона — следующий этап (Tailscale).
- Потоковый синтез и распознавание «на лету»: в MVP сначала фраза целиком, потом ответ.

## Decisions

### 1. Python 3.12 + uv, один репозиторий, один пакет `lumo`
Структура: `src/lumo/core` (ядро), `src/lumo/desktop` (ПК-клиент), `src/lumo/protocol` (общие модели сообщений). Зависимости разбиты на extras: `lumo[core]` — лёгкие, `lumo[desktop]` — torch, faster-whisper и т. д.
- Почему 3.12, а не установленный 3.14: под 3.14 пока нет готовых сборок torch и ctranslate2. uv сам скачает 3.12 в виртуальное окружение, системный Python не меняется.
- Альтернатива: два отдельных репозитория — отклонено, для портфолио и одного разработчика монорепо проще.

### 2. Ядро: FastAPI + WebSocket, протокол JSON
Один эндпоинт `/ws` и `GET /health`. Сообщения — Pydantic-модели с полем `type`: `hello`, `utterance`, `reply`, `confirm_request`, `event`, `error`. Токен передаётся в `hello`; по умолчанию сервер слушает `127.0.0.1`.
- Почему WebSocket, а не REST: ядру нужно самому присылать события (таймеры), а клиенту на Android будет проще держать одно соединение.
- Альтернатива: gRPC — отклонено, это лишняя сложность для Android и отладки.

### 3. LLM: DeepSeek через OpenAI-совместимый SDK
Пакет `openai` с `base_url=https://api.deepseek.com`, модель `deepseek-chat` (задаётся в `.env`). Навыки передаются как `tools`. Перед вызовом формируется системный промпт: персона, текущие дата и время, часовой пояс, факты о пользователе, недавняя история.
- Абстракция `LLMClient` позволяет позже подключить другого провайдера или локальную модель.
- В тестах вместо сети используется фейковый `LLMClient` со сценарными ответами.

### 4. Навыки: модули в `core/skills/`, декоратор и схема на Pydantic
Навык — функция с декоратором `@skill(name, description, confirm=False)`, параметры — Pydantic-модель, из которой генерируется JSON Schema для `tools`. Реестр обнаруживает модули через импорт пакета при старте.
- Подтверждение реализовано в ядре, а не в LLM: ядро сохраняет «ожидающее действие» и проверяет следующую реплику по словарю согласия («да», «давай», «подтверждаю», «ага», «конечно»). Так модель не может «сама себе» подтвердить опасное действие.

### 5. Память: SQLite (`data/lumo.db`) через стандартный `sqlite3`
Таблицы: `facts(id, user_id, text, created_at)`, `messages(id, user_id, device_id, role, content, created_at)`, `timers(id, user_id, kind, label, fire_at, status, created_at)`, `pending_events(...)`.
- Вспоминание «по смыслу»: в MVP все факты (до 200) добавляются в системный промпт, и смысл понимает сама LLM. Это дёшево и точно. Когда фактов станет больше, добавим векторный поиск (sqlite-vec + локальная модель эмбеддингов) — это изменение внутри ядра, протокол не меняется.
- Контекст разговора: последние сообщения пользователя за 30 минут со всех устройств (не более 20). Это и даёт «перешёл с ПК на телефон — Вальтер помнит».
- Альтернатива: Postgres или облачная БД — отклонено, это лишняя инфраструктура и деньги.

### 6. Таймеры: asyncio-планировщик поверх таблицы `timers`
При старте ядро загружает активные записи. Просроченные срабатывают сразу, для остальных ставятся `asyncio`-задачи. Относительное время («завтра в 9») переводит в ISO-дату сама LLM: она знает текущее время из промпта. Навык только проверяет, что дата в будущем и в допустимых границах.
- Альтернатива: APScheduler — отклонено, для такого объёма хватает своих ~100 строк, и их проще тестировать.

### 7. Слово-активатор: Vosk с ограниченной грамматикой, за интерфейсом `WakeWordDetector`
Маленькая русская модель Vosk (~45 МБ) с грамматикой `["вальтер", "[unk]"]` срабатывает на «Вальтер» сразу, без обучения, и работает на CPU.
- Альтернатива: openWakeWord со своей моделью — точнее и меньше ложных срабатываний, но модель нужно обучить (бесплатно, в Colab). Делаем это отдельным изменением и подключаем через тот же интерфейс.
- Альтернатива: Porcupine — отклонено, бесплатный тариф ограничен и требует аккаунта.

### 8. Распознавание речи: faster-whisper на CUDA, `compute_type=int8`
Модель по умолчанию — `small` (быстро, ~1 ГБ видеопамяти), можно включить `medium` для точности. Если CUDA недоступна, клиент переходит на CPU. Конец фразы определяет Silero VAD (пауза ~1 с).
- int8, потому что GTX 1660 Ti медленно работает с float16.

### 9. Синтез речи: Silero TTS v4 (ru), за интерфейсом `TTSEngine`
Естественный русский голос, работает на CPU в реальном времени, понимает ударения и «ё». Голос выбирается в `.env` (например, `xenia` или `aidar`).
- Лицензия Silero — некоммерческая (CC BY-NC). Для личного и портфолио-проекта подходит; если проект станет коммерческим, есть замена — Piper (MIT, голоса irina/denis/dmitri) через тот же интерфейс.
- Клонирование голоса (XTTS-v2, F5-TTS) — отдельное изменение.

### 10. Конфигурация: `.env` + `pydantic-settings`, в репозитории только `.env.example`

## Risks / Trade-offs

- [Vosk даёт ложные срабатывания на похожие слова] → настраиваемый порог уверенности; позже заменить на обученную модель openWakeWord.
- [Установка CUDA-библиотек для faster-whisper на Windows (cuBLAS 12, cuDNN 9)] → ставить их как pip-пакеты `nvidia-*`, при сбое автоматически переходить на CPU; описать шаги в README.
- [torch занимает ~2.5 ГБ] → только в extras `desktop`, ядро лёгкое.
- [LLM неверно переведёт «завтра в 9» в дату] → в подтверждении ассистент всегда называет итоговые дату и время, и пользователь сразу видит ошибку.
- [Задержка: STT + сеть + TTS ≈ 2–4 с] → для MVP приемлемо; потоковый ответ — будущая оптимизация.
- [Токен в `.env` — слабая защита] → по умолчанию сервер доступен только с localhost; полноценная авторизация появится вместе с удалённым доступом.

## Migration Plan

Не требуется: первое развёртывание. Запуск — две команды (`lumo-core` и `lumo-desktop`), описанные в README.
